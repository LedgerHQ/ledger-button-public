Rework transaction history datasource around Coin Service account operations and surface richer transaction items (status, kind, direction, fees) in the UI with dedicated Failed and Fees rendering.

Apply a hexagonal split to the transaction-history slice: `TransactionHistoryDataSource` (port) exposes only neutral `TransactionHistoryEntry` / `TransactionHistoryPage` domain types, while all Coin Service-shaped DTOs and the `currencyId` -> network-slug resolution are now confined to `datasource/coinService/`. `FetchTransactionHistoryUseCase` and `ConfirmPendingTransactionsUseCase` now consume the normalized domain types directly and accept `currencyId`, no longer leaking Coin Service concepts (such as the `network` parameter) up through the call graph.

Follow-up (not in this change): apply the same containment pattern to the balance slice. `CoinServiceBalance*`, `CoinServiceTransactionIntent`, and `CoinServiceFeeEstimation*` types currently leak from `balance/datasource/coinService/coinServiceTypes.ts` into `balance/service/DefaultBalanceService.ts` and `balance/model/error.ts`; those should be moved behind the `BalanceDataSource` / `CoinServiceDataSource` ports and renamed `*Dto`, with the service consuming domain-aligned types only.
