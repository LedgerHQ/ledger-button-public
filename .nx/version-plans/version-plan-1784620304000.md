Decouple signed-result types per blockchain family via an inversion-of-control registry (DIP + Open/Closed): `api` owns an empty `SignedResultRegistry` seam and derives the shared `SignedResults` transport union from it, while each family owns its result union in its own folder and augments the registry there (EVM's `EvmSignedResult` now lives in `internal/evm-provider`). `api` no longer references any family code, and adding a family (Solana, BTC, XRP, ...) touches only that family's folder. A compile-time guard fails the build if the registry is empty (guards against `SignedResults` silently collapsing to `never`). Type-level only, no runtime change.
