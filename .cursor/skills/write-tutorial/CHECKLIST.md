# Quality Checklist (Tutorial)

Mark **N/A** only where the criterion explicitly allows it.

- [ ] **Minimum content threshold**: Substantial content (~200+ words, or code + context, or visuals with explanation). *Must have.*
- [ ] **Clear and concise language**: Simple language; avoid unnecessary jargon.
- [ ] **Completeness**: Covers all necessary information; no gaps or unexplained assumptions.
- [ ] **Publication readiness**: No TBD, TBW, WIP, or placeholder text.
- [ ] **Title and structure coherence**: Title matches content; sections follow a logical progression.
- [ ] **Code example completeness**: Complete, executable (full functions, imports, setup); standard syntax; context for where/when to use.
- [ ] **Workflow completeness**: Self-contained or clearly placed in a larger workflow with prev/next links.
- [ ] **Version information accessibility**: Version requirements for tools/dependencies stated or linked.
- [ ] **Introduction clarity**: Purpose and prerequisites stated up front.
- [ ] **Visual elements effectiveness**: Any diagrams/screenshots are referenced in text and given context.
- [ ] **Cross-document navigation**: Links to prerequisites, related content, and next steps.
- [ ] **Step complexity**: Steps are digestible (ideally ≤5 per section).
- [ ] **Decision points management**: If choices exist, limit to 3–5 per section; explain implications; recommend default. *If no decision points, mark N/A.*
- [ ] **Image accessibility**: Images have meaningful alt text. *If no images, mark N/A.*
- [ ] **Warning and note implementation**: If risks or caveats exist, 2–3 per major section max; clear, action-oriented. *If not needed, mark N/A.*
