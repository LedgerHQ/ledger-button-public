# Quick reference

Use this when you need a fast lookup without walking the decision tree.

## Table

| If the reader… | Use skill | Folder |
|----------------|-----------|--------|
| Looks up facts (APIs, options, behaviour) | Reference | [write-reference](../write-reference/SKILL.md) |
| Has a specific task and knows what they want | How-to guide | [write-how-to-guide](../write-how-to-guide/SKILL.md) |
| Is new and learning by doing | Tutorial | [write-tutorial](../write-tutorial/SKILL.md) |
| Wants context, background, or "why" | Explanation | [write-explanation](../write-explanation/SKILL.md) |

## Key questions in one line

- **"What is X? What does Y do? What are the options?"** → Reference  
- **"How do I do X?"** (reader already competent) → How-to  
- **"I'm new; walk me through something."** → Tutorial  
- **"Why is it like this? How does it fit? What are the trade-offs?"** → Explanation  

## When in doubt

- **Tutorial vs how-to**: Tutorial = learning journey (you decide the path). How-to = task (they decide the goal; you give the steps).
- **Explanation vs reference**: Explanation = discussion *about* a topic (why, context, choices). Reference = description *of* the product (what exists, what it does).
- **Mixed purposes**: Prefer one primary type per document. Link to other types (e.g. "For background, see [explanation]; for options, see [reference]") instead of mixing them in one page.
