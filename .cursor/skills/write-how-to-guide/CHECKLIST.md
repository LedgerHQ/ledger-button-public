# Quality Checklist (How-to Guide)

Mark **N/A** only where the criterion explicitly allows it.

- [ ] **Minimum content threshold**: Substantial content (~200+ words, or code + context, or visuals). *Must have.*
- [ ] **Clear and concise language**: Simple language; avoid unnecessary jargon.
- [ ] **Completeness**: Covers all necessary information; no gaps.
- [ ] **Publication readiness**: No TBD, TBW, WIP, or placeholders.
- [ ] **Title and structure coherence**: Title matches content; sections follow logical order.
- [ ] **Code example completeness**: Complete, executable; all variables/imports/setup included; context for where/when to use.
- [ ] **Workflow completeness**: Self-contained or clearly placed in a larger workflow with prev/next links.
- [ ] **Error handling and troubleshooting**: At least 2–3 common errors with solutions; troubleshooting where needed.
- [ ] **Version information accessibility**: Version requirements stated or linked.
- [ ] **Introduction clarity**: Purpose and prerequisites clear.
- [ ] **Visual elements effectiveness**: Diagrams/screenshots referenced and contextualised.
- [ ] **Cross-document navigation**: Links to prerequisites, related content, next steps.
- [ ] **Step complexity**: Digestible steps (ideally ≤5 per section).
- [ ] **Decision points management**: If choices exist, limit to 3–5 per section; explain implications; recommend default. *If no decision points, mark N/A.*
- [ ] **Image accessibility**: Images have meaningful alt text. *If no images, mark N/A.*
- [ ] **Warning and note implementation**: If risks or caveats exist, 2–3 per major section max; clear, action-oriented. *If not needed, mark N/A.*
